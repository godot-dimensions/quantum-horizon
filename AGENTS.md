# Agent instructions for Quantum Horizon

The instructions in this file are for agents that are working in this repository, for Quantum Horizon. It contains an engine fork and custom engine modules in `engine/`, and a Godot project in `project/`. These instructions are redundant with the `README.md` file, so you can skip reading the `README.md` file, unless you need to make changes to the instructions.

When you are working in the repo, pay attention to the organization of files. Top-level file-type-specific folders such as `project/scripts/` are discouraged beyond basic prototyping. Prefer to organize files by feature, so if a script is specific to a scene, place the script in the same folder as the scene.

If you make changes to a `.tscn` file, and Godot is not open: Run `.\engine\scripts\resave_scenes_windows.ps1 -ProjectPath .\project\project.godot` on Windows or `./engine/scripts/resave_scenes_unix.sh --project-path ./project/project.godot` on macOS and Linux. This expects the editor to be built already. This will re-save all `.tscn` files in the project using Godot's editor save behavior, which normalizes the files. Agents may generate and edit `.tscn` files without UIDs, without alphabetized properties, etc, and these problems will be automatically fixed by this script invoking Godot to re-save the files. Ignore leaks and RID allocations, but if there are other errors in the command line output, investigate and fix them. Agents should also review diffs made to the `.tscn` files. If Godot removes nodes, that may indicate a lack of `[editable path="..."]`, but first confirm the path is correct.

When your changes are ready for human review, check if Godot is already running. If so, just inform the user. If not, you may run one of the `run_editor_*` scripts at the root of the repository, depending on your platform. This will update all submodules, build the engine, and run the Godot editor, presenting the project to the human. If the engine files have not changed (likely), add `-DoNotUpdate -SkipIdeSetup` on Windows or `--do-not-update --skip-ide-setup` on macOS and Linux to skip pulling submodule changes and generating IDE files. If you encounter an engine crash (unlikely), add `-Dev` on Windows or `--dev` on macOS and Linux to make a development build of the engine, which will include debug symbols in the stack traces.

If a human makes uncommitted changes, avoid bulldozing them. You can copy files into a gitignored `.backup/` folder as needed.
